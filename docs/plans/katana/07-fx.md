# Katana 07 — Katana FX: effects, transitions and text animations — PLANNED

Part of [../katana.md](../katana.md); §8 there wins. Merged 2026-10-05 by the lead from three inputs: an engine
design (checked against `src/main/main.js`, `comfy-client.js`, `generation/worker.js`), a library and licence pass
(gl-transitions at commit `902218a1b637`, pixi-filters, glfx.js, three.js shaders, Fontsource) and a browser and
Director design. **Where this file and 04 or 06 differ on the renderer, export pictures, transitions, looks or
text, this file wins.** Sizes: **S** under 150 new lines, **M** 150–400, **L** over 400. GLSL and JSON item
files are counted as content, tests in addition.

## 0. The owner's question and the verdict
"CapCut has effects and transition plugins, is it included, and can we build one like CapCut?"

- **Included today?** No. The plans had 12 transitions limited to `xfade` matches, In/Out/Loop text animations
  and LUT looks. No effects library, no text-effects library, no format for adding effects.
- **Can we build it?** Yes. **Katana FX**: every effect, transition and text animation is a WebGL2 shader or a
  data recipe, drawn by **one compositor** used by both the live preview and the export. The shader maths match by
  construction; the source frame matches exactly on a paused or stepped frame and within ±1 frame while playing
  (§1.1, FX0 proves it). Our LGPL ffmpeg no longer limits the pictures. ffmpeg decodes, encodes (`h264_mf`,
  `aac_mf`), mixes sound and renders plain cut segments.

The proposed direction is **accepted with eight changes** (the lead settled where the inputs disagreed):

| # | Change | Why |
|---|---|---|
| 1 | The compositor draws **every** picture in Full Katana: clips, transform, blend, keyframes, grade, text, overlays, effects. Not only "FX". | Deletes most of 04 §5's parity machinery (`sendcmd`, `overlay` on `gbrap`, `blend`, title PNG frames, `lut3d`, the `xfade`-match rule). |
| 2 | Export **decodes with ffmpeg** into raw I420 frames, not WebCodecs. | Frame-exact for constant-rate sources (FX0 proves it on 16–60 fps and a phone VFR clip), every codec the export already reads (ProRes, HEVC without hardware), and **no VRAM**. WebCodecs only later, if decode is the bottleneck (§3.4). |
| 3 | Frames flow through an Electron **`utilityProcess`** (`fx-host`), never the main process. | The main process runs Hono and the UI; ~190 MB/s of frames must not touch it. |
| 4 | Every v1 effect is a **pure function** of (inputs, params, frame, seed). No history from earlier frames. | Segments stay independent, Resume stays exact, the parity test can render any frame alone. Trails and echo come later. |
| 5 | **Two paths per segment, not three.** `plain` (cuts only, ffmpeg, no GPU) or `fx` (compositor). No native `xfade` fast path in Full. | One more path is one more parity test. The fx path costs ~20–30 % over plain because both wait on the same encoder. |
| 6 | The UI never says "pack". It says **Effects** and **effect set**; code uses `fx` and `fxset`. | "Pack assets" already means the board ZIP (01 §8). The guide test bans "pack" next to effect words. |
| 7 | Text animations and title templates are **data** (`anim.json`, `title.json`), not shaders. A small first-party post shader adds glow, flicker and glitch. | No code, exact parity, and a safe path for user presets later. |
| 8 | Write the trivial items ourselves; adapt third-party code only where it is real work. Licence gate per file. | No notice line and no provenance doubt for fades, wipes, vignette, shake. |

**Mini Katana** keeps P3's ffmpeg path and `xfade` dissolve; **FXm** (§9) later adds a join menu and one look.

## 1. The engine: one WebGL2 compositor
### 1.1 The frame graph (pure, shared)
`src/shared/katana/fx/frame-graph.js`: `buildFrame(n, project) → FrameGraph`. No DOM, no GL. Preview, export,
parity tests and the Director use it.

```js
FrameGraph = { n, fps, size: {w, h},
  layers: [   // bottom → top: V1, V2…Vn, T1…, effect-lane (E1) layers interleaved by track order
    { kind: 'clip', clipId, src: {media, frame, matrix: 'bt709'|'bt601', range: 'tv'|'pc'},
      xf: {x, y, scale, rot, crop, flip}, opacity, blend: 'normal'|'multiply'|'screen'|'darken'|'lighten',
      fx: [{item, v, params, seed}], grade: {lut} | null },
    { kind: 'junction', a: <clip layer>, b: <clip layer>, item, v, params, progress },  // replaces both V1 layers
    { kind: 'text', clipId, layout: <glyph runs>, style, anim: {item, phase: 'in'|'loop'|'out', progress}, fx: [] },
    { kind: 'adjust', fx: [...], opacity } ],   // E1 lane clip: runs on the composite below it
  beat: {sinceMs, strength} }                   // measured onsets only; 0 when not measured
```

- **Source frame rule.** `src.frame` comes from `timing.js` with ffmpeg's `fps` rounding (`round=near`), checked
  against a frame-numbered fixture decoded by the real ffmpeg. A paused preview seeks to the middle of that frame
  (`(k + 0.5) / srcFps`) and checks rVFC `mediaTime`: a paused frame is the export's frame; playing may show a
  neighbour. Segment bounds are `clock.js` frame indices, so the Ns sum to the film's frame count exactly. A VFR
  source (phone clip) gets a CFR intermediate (`-fps_mode cfr`, tools queue) if FX0 shows it drifting.
- **Params arrive resolved.** `params.js` applies keyframes, units and beat binding; the compositor does no timing.
- **Frame-relative units.** Params are in fractions of frame height or `px@1080`, scaled by the target size, so a
  ½-quality preview looks like the 1080p export (grain size, blur radius, shake amplitude).
- **Active layers only.** `layer-index.js` (sorted intervals per track): ~0.2 ms for a 2 h, 1,800-clip project.

### 1.2 Passes (`public/js/katana/fx/`, runs in the page or in a Worker on an OffscreenCanvas)
- **Sources** behind one `FrameSource` interface. Preview: 06's pool of 8 `<video>`, uploaded with
  `texImage2D(video)` only when `requestVideoFrameCallback` reports a new frame. Export: three R8 textures (I420
  planes) and a source pass doing YUV→RGB with the probed matrix and range (untagged: BT.709 at 720p and up, else
  BT.601, as Chromium reads them).
- **Working space.** Gamma-encoded BT.709 RGB, premultiplied. gl-transitions are written in gamma, and a gamma
  dissolve matches Mini's `xfade` fade. Items that need light maths (glow, blur, light leak, zoom blur) set
  `linear: true`; the prelude converts with BT.1886 (γ 2.4) and back. The LUT runs unpremultiplied and **last**.
- **Precision.** `RGBA16F` intermediates when `EXT_color_buffer_float` exists (almost every desktop GPU), else
  `RGBA8` with a "reduced precision" flag. The final 8-bit step uses a fixed blue-noise dither seeded per frame:
  deterministic, so preview and export dither alike and stacked grain does not band.
- **Per frame:** (1) per clip: source → effect chain (ping-pong) → transform into frame space; (2) junction: A and
  B into two targets, then the transition; (3) text: SDF glyph quads, then its post chain; (4) composite into an
  accumulator; blend modes are computed in the shader from a ping-pong accumulator (`blendFunc` cannot express
  Multiply or Screen on premultiplied colour); (5) E1 lane clips run on the accumulator; (6) grade LUT (33³ 3D
  texture); (7) output.
- **Output.** Preview draws to the canvas at its backing size (~718×404 × DPR). Export runs a **pack pass**
  (RGB→YUV BT.709 limited, packed I420 in an RGBA8 target `W/4 × 1.5H`): 3.1 MB per 1080p frame instead of 8.3 MB,
  `readPixels` into a `PIXEL_PACK_BUFFER` with a fence and 3 frames in flight; ffmpeg needs no conversion. Not
  `VideoFrame(canvas).copyTo()` (format and colour vary), not WebCodecs `VideoEncoder` (owner decision 1).
- **Shader ABI.** Injected prelude: `#version 300 es`, precision, `u_<param>`, `u_resolution`, `u_frame`, `u_time`,
  `u_seed`, `u_beat`, `u_progress`, `fx_hash()` (integer PCG), `fx_noise`, `toLinear`, `toGamma`. Transitions keep
  gl-transitions' ABI (`transition(uv)`, `getFromColor`, `getToColor`, `progress`, `ratio`); effects write
  `effect(uv)` with `getColor`. Author files may not contain `#`, `uniform`, `in`/`out` or raw `texture(`.
- **Program cache.** Programs compile at project open (`KHR_parallel_shader_compile`), so adding an effect never
  stalls the playhead. Compile + link over 2,000 ms disables the item for the session. Context flags `antialias`,
  `depth`, `stencil`, `preserveDrawingBuffer` all false.
- **Files ≤ 400 lines:** `fx/{compositor 350, passes 300, sources 250, targets 150, programs 200, pack 120, text-gl
  300, sdf 120, text-layout 250, text-anims 300, watchdog 100}.js`, `src/main/{fx-host 250, fx-feeds 200}.js`.

### 1.3 Text
- **SDF glyph atlas**, single-channel R8, 2048² (4 MB). Glyphs drawn with Canvas2D `fillText` at 96 px, turned
  into a distance field by our own Felzenszwalb EDT (`sdf.js`, ~120 lines, no dependency). One entry serves every
  size, so Letter pop scales to 300 % without re-rasterising; outline, glow, shadow and neon come from the
  distance value. Titles over 300 px use a second page at 192 px. LRU per entry.
- **Layout** (`text-layout.js`, pure): graphemes from `Intl.Segmenter`, pen positions from prefix widths (kerning
  matches the browser). Shaped scripts (Arabic, Devanagari, Thai) rasterise per word; per-letter animations fall
  back to per word, and the inspector says so. **Animations** (`text-anims.js`, pure) read `anim.json` and give
  each glyph a transform, opacity and colour from (progress, glyph, word, line, seed).
- **Fonts.** Bundled OFL/Apache fonts only (§6.6), loaded with `FontFace` (`self.fonts` in the worker). No frame
  renders before `fonts.ready`, so a missing system font can never change an export. CJK (Noto Sans CJK, ~16 MB
  per weight) is not bundled: **Settings › Video tools › Caption fonts › Download** on the person's press, as the
  speech model (lead's choice; non-Latin captions show a plain notice until then).

### 1.4 Preview at 60 fps on a 2-hour project
- One rAF loop: clock (06 `clock.js`) → `buildFrame` (~0.2 ms) → `sources.prepare` (pre-seek 1 s ahead) →
  `compositor.draw`. Main thread ≤ 2 ms inside 06's 4 ms; GPU ≤ 8 ms at preview size.
- **Graceful drop.** GPU time over 12 ms for 30 frames steps to ½ quality, then skips `cost: heavy` items, chip
  "PREVIEW SIMPLIFIED". A paused frame always renders in full. Export is never affected.
- **Context loss** shows the last frame, restores (`webglcontextlost` calls `preventDefault()`, or it never
  restores), recompiles, redraws. Never fatal. Hover preview reuses the draw.

## 2. Routing: the plain path and the FX path
`src/shared/katana/fx/route.js` (pure) gives every 04 segment a path:

- **`plain`**: V1 clips with hard cuts only, no overlay, text, grade, effect or transition, constant speed. ffmpeg
  only, **no GPU**, and it always runs, even while ComfyUI renders.
- **`fx`**: anything else, through the compositor. The planner closes a segment early at the V1 join nearest to
  where FX layers start or stop, if that keeps segments ≥ 10 s. Captions make most segments `fx`: ~20–30 % slower.
- **One encode recipe** (`src/shared/katana/encode-recipe.js`, S): plain and fx segments end in the same `h264_mf`
  arguments (profile, GOP, `yuv420p`, time base, BT.709 tags), so the concat demuxer `-c copy` stays safe.
- **Mini Katana** keeps P3's `NormalizeClips` / `JoinClips` (`xfade` fade) for cut and dissolve joins forever. A
  test pins that the compositor's Dissolve matches `xfade` fade on 5 frames (mean ≤ 1/255), so Mini and Full agree.

## 3. The export path
### 3.1 Processes
```
tools-queue job (main/Hono) ── starts ──> fx-host (utilityProcess, src/main/fx-host.js)
        │                                   ├─ capped-ffmpeg decode feeds  (stdout → frames)
        │ MessageChannelMain                ├─ capped-ffmpeg encoder       (frames → stdin, honours 'drain')
        └─ hidden BrowserWindow ── Worker(OffscreenCanvas, WebGL2 compositor) ⇄ port ⇄ fx-host
```

- **Credits.** The worker grants 4 frames per feed; fx-host pauses ffmpeg stdout when credits run out. Out: the
  worker waits for fx-host's ack before reading back more than 3 frames in flight.
- **Exact counts.** N = end − start frame (§1.1); the worker sends exactly N; `-frames:v N` sits beside `-t`. fx-host
  imports `capped-ffmpeg.js`, so the runner stays the only spawner; fx timeout max(120 s, 4 × seglen).
- **Resume.** The segment hash adds the compositor version, each used item's manifest + GLSL hash, font file hashes
  and the encode recipe version. Changing a shader re-renders only the segments that use it.
- **Failures.** `render-process-gone` or context loss: retry that segment once. Twice: "The effects renderer
  stopped at segment 41. Finished segments are kept." and **Resume** (the person's press). The window is destroyed
  in `finally`. The export watchdog (§4.3) stops a hung item.

### 3.2 Commands (all through `capped-ffmpeg.js`, `-t` and `-fs` on every call)
```text
# decode feed, one per visible source (new runner rule: rawvideo to pipe:1 needs -t and a reader byte cap
#   of w*h*1.5*frames + 1 MB, like 01 §6's PCM analysis pipe)
ffmpeg <guards> -ss <in> -i <src> -map 0:v:0 -vf "setpts=(PTS-STARTPTS)/<speed>,fps=30,scale=<fw>:<fh>:flags=bicubic,format=yuv420p"
  -f rawvideo -t <len> pipe:1
# encoder (new runner rule: -f rawvideo -i pipe:0 is the only stdin input allowed; output under the job temp dir)
ffmpeg <guards> -f rawvideo -pix_fmt yuv420p -s 1920x1080 -r 30 -color_range tv -colorspace bt709
  -color_primaries bt709 -color_trc bt709 -i pipe:0 -an <VENC> -frames:v <N> -t <seglen> -fs <cap> -y .cut-tmp/<id>/seg-041.mp4
```

- **Feed size:** the source fitted to the frame × the clip's largest keyframed scale, capped at 2× the frame. A 4K
  source at 100 % does not ship 4K over the pipe. `-ss` before `-i` is ffmpeg's accurate seek; `timing.js` snaps
  `<in>` to a source frame start, so `PTS-STARTPTS` drops no offset. A short feed repeats its last frame (logged).
- **Reverse** keeps 04's rule (≤ 20 s, a `ReverseSources` prep into a temp file, then fed forward).
- **HDR** (PQ, HLG) is refused in fx segments in v1, with a plain reason.
- **Segments are video only.** Sound stays in 04's windowed `MixSound` and `MuxAndStore`, unchanged.

### 3.3 The hidden export window and GPU flags
- `BrowserWindow({show: false, skipTaskbar: true, webPreferences: {sandbox: true, contextIsolation: true,
  backgroundThrottling: false, preload: 'fx-export-preload.cjs'}})`; the preload passes only the MessagePort. It
  loads `GET /katana/:id/fx-export?job=<one-time token>` under the main window's navigation guards. Not offscreen
  rendering (OSR is not frame-exact). No rAF: the worker loop is promise-driven.
- **One flag:** `app.commandLine.appendSwitch('enable-unsafe-swiftshader')`, so a blocklisted GPU gets software
  WebGL2 instead of nothing; Settings › Video tools says "Effects run in software on this PC; export is slower".
  Safe only because navigation is locked to our 127.0.0.1 pages: **owner question B** (katana.md). No
  `ignore-gpu-blocklist`. `app.getGPUFeatureStatus().webgl2` is shown in that Settings row.

### 3.4 Throughput (1080p30, RTX 3060 12 GB class, 6–8-core CPU; FX0 measures it)
| Stage | Per frame | Ceiling |
|---|---|---|
| ffmpeg software H.264 decode, `-threads 2`, per feed | 4–7 ms | 150–250 fps (~100 with 2 feeds in a transition) |
| IPC in, 3.1 MB I420 | 1–2 ms | — |
| Upload + 4–8 passes at RGBA16F | 2–4 ms GPU | ~250 fps |
| Pack + async readback | ~1 ms + latency | — |
| IPC out + `h264_mf` software MFT encode | 10–17 ms | **60–90 fps, the bottleneck** |
| **End to end** | — | **~40–60 fps = 1.3–2× real time** |

Estimates until FX0 measures them; the stages share the CPU, so the pipeline runs below the encoder's ceiling.
**A 2 h film (216,000 frames), honestly:** 6–8-core desktop + GPU ~60–90 min; 4-core laptop or integrated GPU
~2–3 h; software WebGL (owner question B, ~5–15 fps) ~4–12 h; plain ~20–30 % faster; waits for local renders
(§4.2) on top. The sheet times the first segment, then says "about 1 h 10 min · estimated". **Decoders:**
`<video>` + rVFC is exact only when paused (preview); WebCodecs + mp4box.js (BSD-3) is exact but ~600 lines,
Chromium's codecs only (no ProRes; HEVC only with a hardware decoder) and takes VRAM when hardware decodes (FX5,
only if decode is the bottleneck); **the ffmpeg I420 feed** is exact, reads every codec, **no GPU** (v1).

## 4. VRAM and living with ComfyUI (decided)
### 4.1 Budget (ledger in `targets.js`; a refusal is a plain message)
- **Export 1080p, cap 256 MB:** 7 RGBA16F targets (accumulator ×2, layer ping-pong ×2, junction A/B, text; 16.6 MB
  each) ~100 MB, source planes ≤ 8 ~25 MB, glyph atlas + LUTs + blue noise + 3 PBOs ~15 MB.
- **Preview (~718×404 ×2), cap 192 MB:** targets ~25 MB, `<video>` uploads ~30 MB, the rest ~6 MB.
- Chromium's GPU process adds ~200–300 MB. The preview's `<video>` decoders are 06's, not ours.

### 4.2 Policy
1. **Renders always win.** FX never calls ComfyUI's `/free` or `/interrupt` and never delays the GPU worker.
2. **FX segments wait while a local render runs (default).** `src/server/generation/gpu-gate.js` (S) is fed by
   the worker (`worker.current`, non-cloud) and polls ComfyUI `/queue` every 5 s, so jobs started outside the app
   count too. While waiting, the export finishes its frame, frees its texture pool and targets (compiled programs
   stay, < 64 MB), and renders **plain segments out of order** meanwhile. Status strip, blue: "EXPORT · Effects
   wait for the render on the graphics card · plain parts continue".
3. **Cloud renders never gate** (no local GPU), nor does a ComfyUI URL that is not a loopback address (another
   PC's card). **ComfyUI never waits for Katana**: Generate always wins.
4. **Settings › Video tools › "While a local render runs": Wait (default) / Share the graphics card**, note "Can
   slow renders or make them fail on cards under 16 GB". Share still needs `vramFreeGb ≥ 1.0` from
   `/system_stats` before each fx segment.
5. **A render that starts mid-segment is not blocked.** The current fx segment (≤ 60 s, ~300 MB) finishes; the
   next waits. Windows sysmem fallback (NVIDIA 536+) makes overlap a slowdown, and point 2 avoids even that.
6. **Preview is never gated.** While a local render runs it drops to ½ quality, caps at 30 fps and skips `heavy`
   items (chip "PREVIEW SIMPLIFIED"), so the long draws that risk a driver reset never run beside CUDA. People
   who turned NVIDIA's sysmem fallback off get an out-of-memory error instead of a slowdown; Wait protects them.

### 4.3 TDR safety (a hung shader resets the driver and can kill ComfyUI's CUDA context)
- First-party shaders only in v1 (house rule: no user-supplied code).
- **Lint** (`src/shared/katana/fx/glsl-rules.js`, M): source ≤ 12 KB; only `for` loops with a literal bound ≤ 64;
  no `while`, no dynamic or texture-dependent bounds; ≤ 16 texture taps per fragment with loops multiplied (heavy
  items may declare up to 64); no `discard` in transitions; no `fract(sin())` hash (differs between GPUs).
- **Cost test:** every item at 4K in SwiftShader stays under its tier's budget (light ≤ 120 ms/frame, heavy ≤ 400).
- **Heavy items draw in 4 scissor tiles** with a flush between, in export, so no single submit runs long.
- **Watchdog** (`fx/watchdog.js`, S, `fenceSync` timing; timer queries are often missing). Preview: over 33 ms for
  10 frames bypasses that item there only. Export: over 250 ms on one frame, or context loss twice, stops it: "The
  effect Tape stopped responding on this graphics card. The export stopped at 1:12:04." The item shows "Failed on
  this card" until **Settings › Video tools › Reset effects**.

## 5. The effect set format and security
### 5.1 Layout (shipped inside the app, read only, served by the existing static route)
```
public/fx/
  index.json                 generated: every set, item, version, sha256 of every file
  _samples/                  house sample frames for thumbnails and bin hover loops (our own art)
  katana.core/               one effect set = one folder; set.json {id, version, name, publisher, engine, items}
    transitions/push/        one item = one folder: fx.json, fx.glsl, thumb.webp
      _v1/                   an old major: hidden from the browser, still renders
    effects/tape/  text/type-on/ (fx.json, anim.json)  titles/lower-third/ (fx.json, title.json)  beat/pulse/ (fx.json)
%APPDATA%\Bloop Studio\fx\   FX5 only: user sets
```

### 5.2 Item manifest `fx.json` (zod, `src/shared/katana/fx/schema.js`, M)
```json
{ "id": "katana.core/tape", "version": 2, "engine": 1, "kind": "effect", "span": "clip",
  "name": "Tape", "category": "retro", "tags": ["home video", "retro"], "cost": "light", "linear": false,
  "passes": [{ "shader": "fx.glsl" }], "inputs": ["source", "time", "resolution", "seed"],
  "params": [{ "id": "amount", "label": "Amount", "type": "float", "min": 0, "max": 1, "default": 0.5,
               "step": 0.01, "unit": "%", "animatable": true, "beatable": true }],
  "duration": null, "preview": { "thumb": "thumb.webp" }, "mini": false, "flashes": false,
  "director": { "hint": "home-video memory", "avoid": "dialogue close-ups" },
  "source": { "kind": "original", "license": "LicenseRef-Bloop-Original" } }
```

- `id` `<set>/<item>`, kebab, never reused; `version` an integer major, raised when the look changes visibly.
  `engine`: the compositor API; N and N−1 run (shim), newer is refused "made for a newer Katana".
- `kind`/`span`: `transition`/`junction`, `effect`/`clip` or `range` (E1 lane), `text`, `title`, `beat`/`clip`.
  `cost` `light`|`heavy` (the cost test enforces it; HEAVY chip). `passes` 1–3 fixed (blur H → V → mix).
- `params[].type`: `float`, `int`, `bool`, `enum`, `color`, `angle`, `point`, `direction`; `unit`: `%`, `frameH`,
  `px@1080`, `deg`, `s`, `ms`; label ≤ 18 chars; `animatable` (‹◇› row), `beatable` (beat envelope).
- `duration`: transitions `{min_ms, max_ms, default_ms, max_share: 0.5}`; text `{in_ms, out_ms, loop_ms}`.
- `mini` lists it in Mini's menus; `flashes` routes it through the limiter (§6.5); `director` `hint`/`avoid`
  ≤ 40 chars feed the catalogue; `source` is required (`original`, or `adapted` with `project`, `url`, `commit`,
  `file`, `author` and an SPDX `license`).
- `text` items carry `anim.json` `{unit: glyph|word|line, stagger_ms, ease, tracks: {opacity, x, y, scale,
  rotation, blur, tracking}, post?}`; `title` items `title.json` (slots, plate, fonts, colours, in/out by id);
  `beat` items are presets `{base, params, mod: {param, depth, decay_ms, on}}` with no GLSL.

### 5.3 Gates
1. **Schema**: every reason at once; defaults within ranges; files exist; thumb ≤ 30 KB.
2. **Lint and cost** (§4.3).
3. **Licence** (`scripts/fx-build.mjs`, M, also writes `index.json` and thumbnails rendered by the compositor):
   allowed `MIT`, `BSD-2-Clause`, `BSD-3-Clause`, `Apache-2.0`, `OFL-1.1`, `CC0-1.0`, `LicenseRef-Bloop-Original`.
   Adapted GLSL must keep its `// Author` and `// License` lines verbatim plus `// Adapted for Bloop Studio: …`.
   Shipped GLSL must not contain `shadertoy`, `CC BY-NC`, `GPL` or `lygia`. Names and labels pass the banned-term
   list in `src/shared/` (franchise list plus CapCut, TikTok and other editors' names).
4. **Integrity at load** (`src/server/katana/fx/loader.js`, M): sha256 against `index.json`; a changed file is
   refused ("The effect files are damaged. Reinstall Bloop Studio."). No lint at runtime for first-party sets.

### 5.4 Versions, so old projects still render
Projects store `{fx, v, params, keys, seed}`. The loader resolves the exact major. Unknown params are kept and
ignored; missing ones take the default. A missing id or major is **kept on save**, renders without the effect,
shows a hatched chip "Effect missing: Tape v3" and gets `FX_MISSING` in **Check your cut**. Nothing is swapped
silently. `tests/fx-versions.test.js` renders a v1 fixture after v2 lands.

### 5.5 Third-party sets (FX5, later, owner decision before work starts)
First **data-only user sets** (param presets over our shaders, `.cube` LUTs, `anim.json`, title layouts; no code,
no signature; import runs gates 1 and 3). Then **signed shader sets only** (ed25519, our key in the app) after our
review (lint, cost test, parity). Unsigned shader sets never load.

### 6.1 Transitions (30; common params: duration 0.2–2.0 s, default 0.5, easing)

### 7.1 Full Katana

  **Bring a LUT** become its first category chip). Eight tabs would be ~45 px each at 360 px. **Owner question A.**
- **Filter row** of `.ae-stencil` chips: ALL · ★ FAV · RECENT · categories (EFFECTS: LOOKS · FILM · RETRO ·
  LIGHT · GLITCH · MOTION · FRAME · BLUR · BEAT; TEXT: TEMPLATES · IN · OUT · LOOP · CAPTIONS). Active chip: 2 px
  orange underline (`.ae-stencil--ruled`).
- **Tiles** (2 columns, 160 × 90 `.ae-plate`, `thumb.webp` from the compositor at build): name in `--text-secondary`;
  favourite notch `.ae-key--square` with `aria-pressed`; HEAVY chip (seam grey); `.ae-plate--flash` orange corner

  /katana/fx/favourites/:id` and `POST /katana/fx/recent`, with CSRF; Mini reads the same favourites.
- **Hover preview.** Hover or focus a tile 120 ms: the item applies **temporarily** to the selection (clip 2 s loop,
  junction 1.5 s loop, text plays its In), blue `PREVIEW · Tape · Esc`, no history, no save. No selection: it loops

## 8. The Director
### 8.1 Ops (same names in Mini's `propose_cut_ops` and Full's Ask bar; one all-or-nothing call, ≤ 12 FX ops)
```json
{ "op": "apply_transition", "at": "s3-door | c12", "all_joins": false, "fx": "dip-to-colour", "ms": 600, "params": {} }
{ "op": "apply_effect", "target": "c12 | range | film", "from_s": 62.0, "to_s": 70.5,
  "fx": "grain", "params": { "amount": 0.3 }, "fade_ms": 400, "beat": false }
{ "op": "set_text_style", "clip": "t3 | captions", "template": "lower-third", "anim_in": "type-on",
  "anim_out": "fade-away", "loop": null, "font": "Inter", "size": 64, "plate": true, "colour": "#ffffff" }
{ "op": "remove_fx", "target": "c12 | s3-door | film | t3", "fx": "tape | all" }
```

- **Validator** (`director/cut/fx-validate.js`, `director/katana/fx-validate.js`, sharing `fx/params.js`), every
  reason first: id and kind; params in range; `ms` in the duration rules; ≤ 4 effects per clip; `beat` needs
  measured beats; Mini allows only `mini: true` items and `target: film` (the Look); the edit lock (an effect the
  person placed is theirs unless they name it this turn). The Director never writes keyframes (`fade_ms` only).
- **Refusal:** `op 5: beat effects need the music's beats, and they are not measured. Measure with inspect_cut
  first.` **Done line:** `Done — 2 transitions, 1 look; nothing was rendered or exported.` Notes ≤ 40 chars.
- **`inspect_cut`** adds each clip's effects, each join's transition, the look, text styles, beats measured or not.
- **Catalogue** (`prompts/fx-catalog.js`, S): generated from shipped manifests, sorted, byte-stable, ≤ 2,000 chars
  in the cache-stable half after `EditCraft`: `FX LIBRARY. transitions: dissolve (time or place jump), dip-to-colour
  (end of a chapter), … | looks: grain (texture), tape (home-video memory), … | text: type-on (a note, a date) …`.

### 8.2 Doctrine (`prompts/doctrine-fx.js`, S, appended to `EditCraft`)
```
EFFECTS — the cut carries the story; effects only mark it.
RESTRAINT BY DEFAULT. Add a transition, look, text style or beat effect only when the person asks, names a mood
  ("retro", "dreamy", "more energy"), or their editing style asks for it. Otherwise: cuts, and a dissolve for a
  jump in time or place.
A TRANSITION MUST MEAN SOMETHING: time jump, place change, mood shift, chapter seam, the end. Say which. Never
  inside one scene, never across a spoken line, never on most joins.
ONE FAMILY PER FILM. One transition family and one look, repeated, become the film's grammar.
CHEAP SIGNS: spins, flashes on every cut, heavy shake under dialogue, glitch on a sad scene, a look so strong the
  faces change colour. Avoid them unless asked.
LOOKS ARE SUBTLE. Start near 30 %. Grain and vignette are seasoning. The grade stays last.
BEAT EFFECTS only when asked or for energetic styles (music video, trailer, sport). Downbeats, never under a line.
TEXT. Titles: one animation in, one out. Captions stay readable: plain fade or word by word, never bounce.
SAY IT IN EDITING WORDS. "Faded to black at the time jump, a light grain over the flashback." Never name controls.
```

- Editing style memory (05 §3.8) gains `effects: none | light | bold`, default `none`; only the person's own words
  saved with `remember_edit_style` raise it. With `none`, an unasked turn adds no effect beyond a dissolve.
- **Critic codes:** `TRANSITION_HEAVY` (> 30 % of joins non-dissolve, > 6 joins), `FX_ON_LINE` (a transition
  over a spoken line), `FX_STACK` (> 3 effects on a clip), `FX_MISSING`.
- **Owner rules hold:** never renders, never exports, never names a control unprompted (03 §6 grep). How-to answers
  come from the registry (05 §4.2): new ids in `controls/bin-fx.js`, `viewer.js`, `timeline.js`, `inspector-fx.js`,
  `dock.js`, `export.js`, `settings.js`. "Can I add my own effects?" → "Not yet. Katana ships its own effects. You
  can bring a colour LUT (.cube) in Effects › Looks."

## 10. Tests (`node --test`; never the real GPU)
- **Pure:** `fx-frame-graph` (layer order, junction replaces V1, E1 scope, frame rounding), `fx-params`, `fx-route`,
  `fx-schema` (every shipped item valid), `fx-glsl-rules`, `fx-text-layout` (graphemes, per-word fallback),

  `fx-prefs` (CSRF), `fx-licences` (allowlist, headers kept, banned words), `fx-loader` (tampered file refused).
- **`gpu-gate`** with a fake worker and fake ComfyUI: fx waits, plain continues, cloud does not gate, Share needs 1 GB.
- **`fx-host`** with a fake spawn: decode feed has `-t` and a byte cap; encoder has `-t`, `-fs`, `-frames:v`;
  credits pause the feed; exactly N frames; a killed child fails the segment; temp files swept.
- **Golden-frame parity** (`tests/katana-fx-parity.test.js`): spawns Electron from the dev dependency with
  `--use-angle=swiftshader --enable-unsafe-swiftshader` (software, deterministic, CI-safe); skipped with a reason
  when the binary is missing. 12 frames: Dissolve mid-point, Zoom blur at 0.3, Glitch, Grain + Vignette, LUT
  grade, Multiply overlay, keyframed scale + rotation, Letter pop mid-In, Word by word on word 3, Neon flicker,
  E1 lane clip, a 9:16 crop with red text on blue. Three comparisons: preview path vs export path RGBA (mean 1.0,
  99.5th percentile 4/255; Chromium's chroma upsampling differs from ours on saturated edges, so no max); export
  path vs checked-in SwiftShader goldens (max 3/255, mean 1.0); with `vendor/ffmpeg`, the encoded segment decoded
  back vs the compositor (luma mean 2.0, max 8). Plus Dissolve vs `xfade` fade on 5 frames (Mini parity).
- **Source frames** (`tests/katana-fx-frames.test.js`, needs `vendor/ffmpeg`): FX0's frame-number fixtures as a
  test; the paused preview and the feed pick the same source frame. **Context loss**: `WEBGL_lose_context` mid-
  segment retries once and gives identical frames. **`gpu-gate`**: a non-loopback ComfyUI URL never gates.
- **Cost test** (§4.3). **Manual:** `npm run fx:parity -- --gpu` compares hardware preview and export on a real PC.
- **Guards stay:** `cut-uses-capped-ffmpeg` (fx-host imports the runner), 05 §5.8 licence grep (fewer filters now),
